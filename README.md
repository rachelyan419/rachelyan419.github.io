# rachelyan419.github.io

## 1. What this repository is

This repository contains the source code for the personal website and blog of Rachel Yan, built with [Quarto](https://quarto.org/) and published with GitHub Pages at <https://rachelyan419.github.io>. The blog includes two computational posts, one in Python (`posts/penguins-python/`) and one in R (`posts/gapminder-r/`), whose tables and figures are generated by code every time the site is rendered.

The Python environment is pinned with `uv` (`pyproject.toml`, `uv.lock`, `.python-version`) and the R environment is pinned with `renv` (`renv.lock`, `.Rprofile`, `renv/activate.R`). Installed packages (`.venv/`, `renv/library/`), Quarto's cache (`.quarto/`, `*.quarto_ipynb`), `_site/`, and personal system files (`.DS_Store`, `.Rhistory`, `.Rproj.user/`) are not committed; they are listed in `.gitignore`.

## 2. What to install first

Install these tools before building the site. These are the versions used to build it:

| Tool | Version | Install |
|----|----|----|
| Git | any recent version | <https://git-scm.com/downloads> |
| Quarto | 1.10.18 | <https://quarto.org/docs/get-started/> |
| uv | 0.12.6 | <https://docs.astral.sh/uv/getting-started/installation/> |
| R | 4.6.1 | <https://cran.r-project.org/> |

You do not need to install Python, `renv`, or any packages yourself: `uv` downloads Python 3.14 if needed, `renv` installs itself the first time R starts in this repository, and all packages are installed from the lockfiles in section 3.

To check the installed versions, run in a terminal:

``` bash
git --version
quarto --version
uv --version
R --version
```

## 3. Build the site

Run every command from the **top level of the repository** (the folder that contains `_quarto.yml`). Commands marked **Terminal** are run in a terminal (prompt `$`). Commands marked **R** are run inside an R session (prompt `>`).

**Step 1 (Terminal).** Clone the repository and move into it:

``` bash
git clone https://github.com/rachelyan419/rachelyan419.github.io.git
cd rachelyan419.github.io
```

**Step 2 (Terminal).** Create the Python environment from `uv.lock`. This creates a `.venv/` folder with the exact package versions used:

``` bash
uv sync
```

**Step 3 (Terminal).** Start R from the top level of the repository. R reads `.Rprofile`, which activates `renv`. The first time, `renv` downloads and installs itself:

``` bash
R
```

**Step 4 (R).** Restore the R packages from `renv.lock`. When asked `Do you want to proceed? [Y/n]`, type `Y`. If renv reports that the library is already synchronized, no action is needed. Then quit R, and type `n` if asked to save the workspace:

``` r
renv::restore()
q()
```

**Step 5 (Terminal).** Render the whole site. Use `uv run` so that Quarto runs the Python code with the project's `.venv/`. The R code uses the project's `renv` library automatically, because Quarto starts R from the top level of the repository:

``` bash
uv run quarto render
```

If the Python code uses the wrong environment, delete Quarto's cache and render again (Terminal):

``` bash
rm -r .quarto
uv run quarto render
```

## 4. Where the built site lands and how to open it locally

The built site is written to the `docs/` folder, which is the folder GitHub Pages publishes. To view it locally, open `docs/index.html` in a web browser, or run the following in a terminal from the top level of the repository, which opens the site in your browser (press `Ctrl + C` to stop it):

``` bash
uv run quarto preview
```

## 5. Where the data comes from

| Post | Dataset | Source | Licence | Loaded with |
|----|----|----|----|----|
| Python | Palmer Penguins | [palmerpenguins](https://allisonhorst.github.io/palmerpenguins/), collected by Dr. Kristen Gorman and the Palmer Station Antarctica LTER | CC0 | `palmerpenguins` Python package |
| R | gapminder | [gapminder](https://cran.r-project.org/package=gapminder) R package by Jennifer Bryan, data from the [Gapminder Foundation](https://www.gapminder.org/data/) | CC0 | `gapminder` R package |

No data files are committed to this repository. Both datasets are bundled inside their packages, so they are installed together with the packages in steps 2 and 4.

**Network:** an internet connection is needed for steps 1 to 4, to clone the repository and install the packages. The build itself (step 5) does **not** need the network: no data is downloaded at render time.
